# Reviewed squash landing

This is the mutation procedure for `/git-flow:land`. Read [shared safety](safety.md) first. No command here grants authority on its own.

1. Require `solo-shaped-kanban`, a clean feature branch and a named base. The current contributor must own the work or have exact authority. Refuse detached HEAD, the base branch itself, untracked or dirty files, and an in-progress merge, rebase, cherry-pick or revert. Do not reuse a review cache.
2. Fetch the base with `verification-source.ts`. Pin the root, remote destination, base ref, full base OID, HEAD OID and tree OID. Require `git merge-base --is-ancestor <baseOid> <headOid>` to succeed. If it fails, use the separately authorized rebase workflow and restart verification and review. Require a nonempty tree diff and inspect the full `git diff <baseOid> <headOid>`, including binary and submodule changes.
3. Run `/core:verify` against that fetched base. Require all relevant gates to pass. Present the complete diff or a reviewable diff view and a clear summary. Record when it was presented. A commit or push request from before this presentation is not landing authority. Only proceed when the user explicitly asks to land this presented change in the current conversation.
4. Run a fresh `/core:review` on that exact worktree, HEAD and fetched base. Require its independent reviewer, approved result, zero blocking findings, current tree OID and no dirty patch. If delegation is unavailable or any source evidence is missing, stop. Record a review attestation in the report: reviewer identity, result, full HEAD/tree/base OIDs, root, remote/base ref and verification evidence. This report is evidence, not a reusable approval token. `/core:review` does not authorize landing.
5. Refetch immediately before preparing the squash. Require the same base OID, HEAD, tree, clean status, mode and destinations. Confirm the explicit ask still covers this diff. Stop on any change. Create a reviewed commit message in a temporary file: imperative subject of at most 72 characters, optional explanation, no attribution and no closing issue references unless explicitly requested.
6. Build one squash commit from the reviewed tree and the fetched base as its only parent. `git commit-tree <treeOid> -p <baseOid> -F <message-file>` prints the candidate OID. This creates a new object without changing a branch, index or checkout. Use the contributor's verified Git identity. If repository policy relies on commit hooks or signed commits, run its documented validation and signing path, or stop. Do not assume `commit-tree` ran `commit-msg` hooks.
7. Verify the candidate is a commit, has exactly the fetched base as its one parent, has exactly the reviewed tree, and is one commit ahead of the base. Check `git rev-list --count <baseOid>..<candidateOid>` equals `1`, `git rev-parse <candidateOid>^` equals the base, and `git rev-parse <candidateOid>^{tree}` equals the reviewed tree. Inspect `git show --format=fuller --stat <candidateOid>`. Never merge a mutable feature ref at this point.
8. Read the exact live base ref with `git ls-remote --refs <remote> refs/heads/<baseBranch>`. Require one full OID equal to the fetched base. Recheck HEAD, tree, clean status, mode and destinations. Push only the candidate: `git push <remote> <candidateOid>:refs/heads/<baseBranch>`. Keep normal pre-push hooks enabled. Never use force, a bypass option, an admin override or a retry that drops a failed gate. Because the candidate's parent is the pinned base, an intervening divergent base advance makes this normal push fail.
9. Read back the live base. Success requires it to equal the candidate OID. If push or readback is uncertain, inspect the remote before any retry and report incomplete. Do not rewrite the base to repair uncertainty. Leave the source branch and checkout intact. Report the squash OID, previous base, reviewed HEAD/tree, reviewer, checks, push and readback results.

Do not run deployments, start CI workers or change production state. The report may mention a repository-documented post-land command for the user to run. Landing does not authorize it.
