---
name: merge
description: Merge an authorized, approved PR with green required checks and a pinned head commit. Refuse admin bypass and dirty worktrees.
---

Requires `core` for `/core:verify` and `/core:review`. Read `${CLAUDE_PLUGIN_ROOT}/docs/safety.md` and `${CLAUDE_PLUGIN_ROOT}/docs/workflow-modes.md`.

1. Inspect read-only state first. Resolve mode. Refuse in `solo-shaped-kanban` and point to `/git-flow:land`. Missing or unknown mode blocks merge with the setup message. Require a clean worktree and no in-progress Git operation. Never stash or discard changes automatically.
2. Resolve the explicit repository and open PR. Read author, actor, head repository/branch/OID, base repository/branch, draft state and URL. Require the PR base to match the intended delivery base, or an explicitly approved lower layer in a stack. Apply the author gate before any checkout, branch or GitHub mutation. The author performs the merge by default. A foreign-author operation requires exact user authorization. Refuse fork branch handling in this batch.
3. Require the current checkout to contain the exact PR head. If not, report the mismatch and obtain authority for a clean checkout before verification. Fetch the PR's actual base with `verification-source.ts` and pin its full OID. Inspect the immutable diff. Run `/core:verify` and a fresh `/core:review`. Require relevant local gates to pass and no blocking review findings. Missing evidence blocks merge. A successful push is not check evidence.
4. Read all relevant GitHub reviews, threads and required checks, including every page. Require at least one current-head approval from a human other than the author. Determine each reviewer's latest effective review, ignoring dismissed reviews; a later change request supersedes an earlier approval. A bot or self-approval does not count. Require repository CODEOWNERS approvals, no active change requests and no unresolved blocking threads. Incomplete pages or unavailable review state block merge.
5. Inspect `gh pr checks <number> -R <repository> --required` and the repository's protection or ruleset requirements. Require every required check to be green for the exact head. Pending, failing, canceled, timed-out or unknown required results block merge. A skipped or neutral check is not green unless the repository explicitly documents that required result as acceptable. An empty result is acceptable only when complete protection evidence confirms that no checks are required. Do not confuse an API failure with no requirements. Respect merge queues; if a queue cannot pin this head, stop and report the supported path.
6. Immediately reread the mode, destinations, author, actor, PR state, head OID, base OID, approvals and required checks. Stop on drift and refresh the affected evidence. Confirm this PR and squash operation are within the user's merge request. Run `gh pr merge <number> -R <repository> --squash --match-head-commit <headOid>`. Never use `--admin`, bypass protections or enable automatic merging as a substitute for these gates. Do not retry around a rejection.
7. Read back the merged state and merge commit OID. If the provider reports only queue admission, report pending rather than merged. Leave local and remote branch cleanup for a separately scoped request. Report the URL, actor and author, pinned OIDs, review and check evidence, merge command result and final state. Do not deploy or start workers.
