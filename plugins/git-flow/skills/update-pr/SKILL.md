---
name: update-pr
description: Update the current PR title and visible description from its actual diff. With --title-description-only, change metadata only and preserve test evidence.
---

Requires `core` for `/core:verify` when new verification is requested. Read `${CLAUDE_PLUGIN_ROOT}/docs/safety.md`, `${CLAUDE_PLUGIN_ROOT}/docs/workflow-modes.md` and `${CLAUDE_PLUGIN_ROOT}/docs/pr-copy.md`.

1. Inspect the explicit repository and open PR read-only. Resolve mode; require `pr` before editing. Refuse in solo mode and point to `/git-flow:land`. Unknown or malformed mode shows the setup message and stops metadata mutation. An absent declaration resolves to `pr`. Resolve author, actor and exact head/base facts. Apply the author and payload gate before a PR edit. Do not check out a different branch or update another author's PR without the relevant authority.
2. Fetch the PR's actual base with `verification-source.ts`. Require the local HEAD to equal the PR head for code-derived claims. Read the immutable diff and complete existing title/body. Save the original body and head OID. If a matching worktree is unavailable, report that evidence gap and stop rather than treating another checkout as the source.
3. `--title-description-only` permits only title and description edits. Do not edit code, commit, push, rebase, merge, post reviews or change issue state. In the ordinary workflow, new verification may run through `/core:verify` when within scope. Updating metadata never grants permission for additional code changes.
4. Draft the title and Summary from actual behavior. Preserve the existing test-plan items, checkbox states and output, Plan output, Rollback, and any legacy `review-scope/v1` comment byte for byte. Alter test evidence only for newly collected results or an expressly requested correction; identify the reason. Do not add a hidden contract or treat the legacy comment as an approval. Keep issue URLs non-closing unless the user asks to close. Do not infer project lifecycle decisions from historical process docs.
5. Repair escaped backticks only in the local draft, then inspect the resulting text. Use plain text editing or `jq`; no network repair helper is needed. Run `check-pr-copy.ts --title-file <title-file> --body-file <candidate-file> --original-body-file <original-file>` and repository copy checks. Pass `--allow-closing-issues` only for the explicit closing request. If an optional copy editor is installed, it may review the final draft. Fix errors before proceeding.
6. Show the final title/body change when exact payload authorization is needed. Reread author, actor, mode, head, title and complete body immediately before editing. If the head or original metadata changed, stop and reconcile with the new source rather than overwriting it. Use one `gh pr edit <number> -R <repository> --title <exact-title> --body-file <candidate-file>`. Titles keep backticks around code names; pass the title single-quoted, as in ``--title 'Set `name` as the base branch'``. Do not bundle a code push into this operation. Optional guard hooks may require their documented contribution path.
7. Read back the exact title and body. Report the URL, source OIDs, changed metadata, preserved evidence, copy-check result and edit/readback result. If already correct, report no change and do not write.
