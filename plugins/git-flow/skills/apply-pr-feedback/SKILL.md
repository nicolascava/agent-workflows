---
name: apply-pr-feedback
description: Inspect PR review feedback, apply justified fixes with verification, and reply or resolve threads only for authorized exact payloads.
---

Requires `core` for `/core:tdd` and `/core:verify`. Read `${CLAUDE_PLUGIN_ROOT}/docs/safety.md`, `${CLAUDE_PLUGIN_ROOT}/docs/workflow-modes.md` and `${CLAUDE_PLUGIN_ROOT}/docs/pr-copy.md` for plain writing.

1. Read-only inspection runs first. Resolve mode; require `pr` before this workflow's mutations. In solo mode, refuse PR feedback handling and point to `/git-flow:land` for delivery. An unknown or malformed declaration shows the setup message. An absent declaration resolves to `pr`. Resolve the explicit repository and open PR, author, actor, base and exact head. Apply the author gate before edits, commits, pushes, replies or resolution. Refuse fork branch mutation. Require the correct branch at the published PR head and a clean starting tree.
2. Fetch complete review threads, comments, reviews and changed files, following all pagination including nested thread comments. Use explicit repository/PR IDs. A partial page, missing author or failed request is incomplete. Keep root comment IDs for REST replies and thread node IDs for GraphQL resolution. They are different identifiers.
3. With `--author <login>`, filter by the normalized login, case-insensitively, treating a terminal `[bot]` suffix consistently. Read each selected thread's full context, including later replies by other authors. Do not hide objections by filtering individual comments out of an included thread. Do not reopen already resolved threads without a reason.
4. Triage every selected unresolved thread as apply, modify or skip. Read the current code and test the claim. Apply justified feedback, adapt partially correct feedback, and record a concrete reason for skipping it. A reviewer comment does not automatically expand the task scope. Stop for a scope decision when it materially changes the intended behavior.
5. Use `/core:tdd` for behavior changes needing tests. Make scoped fixes, then run `/core:verify` against the PR's freshly fetched base. Require relevant gates to pass. Reread the PR head before committing or pushing; if another writer advanced it, stop and reconcile. Commit with an imperative message and push only the feature branch, normally and without force. Verify the remote head equals the fixed commit. A failing gate does not justify marking a thread resolved.
6. Draft a concise reply for each selected thread that states the outcome or reason, with commit or check evidence where useful. Prepare the complete exact payloads before posting: repository, PR, root comment/thread IDs, reply bodies and proposed resolutions. Show them as reviewable drafts and obtain authorization for posting and resolution unless that exact scope and text are already authorized. Foreign-author changes also need the author gate's exact-operation authorization. A general request to inspect feedback is not permission to post.
7. Recheck the author, actor, PR head and full current thread before each write. If the thread or code changed, stop and reconcile the affected payload. Use a JSON `replies` array with `threadId`, `rootCommentDatabaseId` and `body` for each reply. Use the SHA-256 digest of the exact payload file bytes shown to and approved by the user. Run `bun "${CLAUDE_PLUGIN_ROOT}/bin/post-review-reply.ts" --repo <owner/name> --pr <number> --payload <payload-file> --thread-id <node-id> --root-comment-id <root-comment-id> --sha256 <digest>`. Add `--resolve` only for an authorized thread after its fix or accepted explanation is confirmed. The guard reads back the reply before resolving and confirms resolution. After a nonzero exit at or after posting, reread the thread before rerunning because the reply may already exist. Never send unreviewed text or silently resolve a thread after a failed reply.
8. Read back every written reply and resolution. Report applied/modified/skipped threads with reasons, commits and full source OIDs, verification, push status, posted reply links, resolved thread IDs and failures. If only code work was authorized, leave replies as drafts and threads unchanged. Do not merge, change the PR description or issue state.
